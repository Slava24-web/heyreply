## 1. Назначение и цели

### 1.1. Проблема
Соискатель откликается на десятки и сотни вакансий на разных площадках (hh.ru, LinkedIn, Хабр Карьера, Telegram-каналы, сайты компаний). Отклики теряются, непонятно, кто ответил, какая площадка работает, какие должности и зарплатные ожидания дают больше приглашений.

### 1.2. Цель продукта
Дать пользователю инструмент, который:
1. Позволяет **внести отклик за 10–15 секунд** сразу после отправки резюме.
2. Хранит всю историю откликов и смену их статусов.
3. Строит статистику и воронку, по которой видно, **насколько эффективна стратегия поиска**: какие площадки, должности, локации и зарплатные вилки конвертируются в интервью и офферы.

### 1.3. Ключевые метрики успеха продукта
- Медианное время добавления отклика — **≤ 15 с** (замер от открытия формы до сохранения).
- Добавление отклика с клавиатуры без мыши — **100 % полей доступны**.
- Время загрузки дашборда (до 5 000 откликов) — **≤ 1,5 с** (LCP).

## 5. Функциональные требования

### 5.1. Регистрация, вход и личный кабинет

**FR-AUTH-1. Регистрация** — e-mail + пароль (мин. 8 символов, буква и цифра), имя. Подтверждение e-mail письмом (этап 2 — допускается без подтверждения в MVP).

**FR-AUTH-2. Вход** — e-mail + пароль. После 5 неудачных попыток за 15 минут — задержка/блокировка на 15 минут.

**FR-AUTH-3. JWT-схема**
- **Access-токен**: срок жизни 15 минут, подпись HS256/RS256, payload: `sub` (userId), `email`, `iat`, `exp`.
- **Refresh-токен**: срок жизни 30 дней, хранится в **httpOnly, Secure, SameSite=Lax cookie**, в БД хранится только его хэш.
- **Ротация**: при каждом `/auth/refresh` выдаётся новая пара, старый refresh инвалидируется. Повторное использование старого refresh-токена → отзыв всех сессий пользователя (защита от кражи).
- Access-токен передаётся в httpOnly cookie (предпочтительно) либо в памяти клиента + заголовок `Authorization: Bearer`. В `localStorage` токены **не хранить**.
- Next.js middleware проверяет наличие сессии и редиректит неавторизованных на `/login`.
- Защита от CSRF: SameSite cookies + проверка заголовка `Origin` на мутирующих запросах.

**FR-AUTH-4. Выход** — удаление refresh-токена текущей сессии. Опция «Выйти на всех устройствах».

**FR-AUTH-5. Восстановление пароля** — ссылка с одноразовым токеном (срок 1 час) на e-mail.

**FR-AUTH-6. Личный кабинет / профиль**
- Имя, e-mail, аватар (инициалы-монограмма по умолчанию).
- Смена пароля.
- Список активных сессий (устройство, дата) с возможностью завершить.
- Настройки: язык, тема, валюта по умолчанию, тип зарплаты по умолчанию (gross / net), порог «гостинга» в днях, начало недели.
- Экспорт всех данных (CSV / JSON), удаление аккаунта с подтверждением.

### 5.2. Быстрое добавление отклика (ключевой сценарий)

**Принцип:** обязательны только **Компания** и **Должность**. Всё остальное — опционально и подставляется по умолчанию.

**FR-ADD-1. Точки входа**
- Кнопка «+ Отклик» в шапке (всегда видна, на мобильных — плавающая кнопка).
- Горячая клавиша **N** (или **Ctrl/⌘ + K → «Новый отклик»**).
- Форма открывается как боковая панель (desktop) / bottom sheet (mobile) поверх текущего экрана — пользователь не теряет контекст.

**FR-ADD-2. Поля формы**

| Поле | Тип | Обяз. | Поведение |
|---|---|---|---|
| Компания | Combobox с созданием | Да | Автофокус. Поиск по справочнику по мере ввода, если нет совпадения — пункт «+ Создать „…“» |
| Должность | Combobox с созданием | Да | Аналогично. Подсказки сортируются по частоте использования |
| Ссылка на вакансию | URL | Нет | При вставке URL источник определяется по домену автоматически (hh.ru → HeadHunter, linkedin.com → LinkedIn, career.habr.com → Хабр Карьера и т. д.) |
| Источник | Combobox с созданием | Нет | Предустановки: HeadHunter, LinkedIn, Хабр Карьера, SuperJob, Telegram, Сайт компании, Рекомендация, Другое |
| Локация | Combobox с созданием | Нет | Город/страна из справочника |
| Формат работы | Сегментированный переключатель | Нет | Офис / Гибрид / Удалённо |
| Зарплата | Два числа «от — до» | Нет | Форматирование разрядов при вводе (150 000) |
| Валюта | Select | Нет | По умолчанию из настроек (RUB, USD, EUR, + произвольная) |
| Gross / Net | Переключатель | Нет | По умолчанию из настроек |
| Дата отклика | Date picker | Нет | По умолчанию — сегодня; быстрые кнопки «Сегодня», «Вчера» |
| Статус | Select | Нет | По умолчанию «Отправлен» |
| Сопроводительное письмо | Чекбокс | Нет | Для аналитики: влияет ли письмо на ответы |
| Заметка | Textarea | Нет | Свободный текст, Markdown-lite |
| Теги | Multi-combobox с созданием | Нет | Например «мечта», «стартап», «реферал» |

**FR-ADD-3. Справочники с автодополнением (creatable combobox)**
- Каждое новое значение компании, должности, локации, источника, тега **сохраняется в справочник пользователя** при сохранении отклика.
- В выпадающем списке: сначала совпадения по началу слова, затем по вхождению; внутри групп — по частоте использования и дате последнего использования.
- Поиск нечувствителен к регистру и к «ё/е»; нормализация пробелов. Дубликаты (`Яндекс` и `яндекс `) не создаются — используется существующая запись.
- Подсветка совпавшей части текста.
- Максимум 8 подсказок, остальное — прокруткой.
- Справочники можно редактировать отдельно: переименовать, объединить дубликаты (merge), удалить неиспользуемые значения.

**FR-ADD-4. Ускорители ввода**
- **«Сохранить и добавить ещё»** (Shift + Enter) — форма очищается, кроме источника, локации, формата и даты (серийный ввод).
- **«Повторить последний»** — предзаполняет форму значениями последнего отклика, кроме компании.
- **Enter** — сохранить, **Esc** — закрыть (с подтверждением, если есть несохранённые данные).
- Tab-навигация по всем полям в логичном порядке.
- Черновик формы сохраняется локально при случайном закрытии.
- Предупреждение о дубле: если отклик в ту же компанию на ту же должность уже был за последние 30 дней — неблокирующее уведомление со ссылкой на прошлый отклик.

**FR-ADD-5. Обратная связь**
- Оптимистичное добавление строки в список, тост «Отклик добавлен» с кнопкой «Отменить» (5 с).

### 5.3. Список откликов

**FR-LIST-1. Представления** (переключатель, выбор запоминается):
1. **Таблица** — основной вид.
2. **Канбан** — колонки по статусам, перетаскивание карточки меняет статус.
3. **Лента** (компактный список) — для мобильных устройств.

**FR-LIST-2. Колонки таблицы** (настраиваемые: показать/скрыть, порядок, ширина):
Дата · Компания · Должность · Статус · Источник · Локация · Формат · Зарплата · Дней без ответа · Последнее обновление · Теги.

**FR-LIST-3. Поиск и фильтры**
- Глобальный поиск по компании, должности, заметке.
- Фильтры: статус (мульти), источник, должность, локация, формат, диапазон дат, диапазон зарплаты, теги, «только без ответа > N дней».
- Фильтры отображаются чипами над таблицей, сбрасываются по одному или все сразу.
- Состояние фильтров синхронизируется с URL (можно сохранить ссылку).
- Сохранённые представления (этап 2): «Активные», «Интервью на этой неделе».

**FR-LIST-4. Сортировка** по любой колонке, по умолчанию — дата отклика, по убыванию.

**FR-LIST-5. Пагинация** — курсорная, бесконечная прокрутка с виртуализацией строк.

**FR-LIST-6. Массовые действия** — выделение чекбоксами: сменить статус, добавить тег, удалить, экспортировать.

**FR-LIST-7. Быстрая смена статуса** — клик по бейджу статуса прямо в строке открывает поповер со списком статусов (без перехода на карточку).

**FR-LIST-8. Пустые состояния** — для нового пользователя: иллюстрация, короткий текст и CTA «Добавить первый отклик» + подсказка про горячую клавишу N.

### 5.4. Статусы и редактирование отклика

**FR-STATUS-1. Набор статусов**

| Код | RU | EN | Этап воронки | Тип |
|---|---|---|---|---|
| `APPLIED` | Отправлен | Applied | 1. Отклик | Активный |
| `VIEWED` | Просмотрен | Viewed | 1. Отклик | Активный |
| `SCREENING` | Скрининг с HR | HR screening | 2. Ответ | Активный |
| `TEST_TASK` | Тестовое задание | Test task | 3. Проверка | Активный |
| `INTERVIEW` | Интервью | Interview | 4. Интервью | Активный |
| `FINAL_INTERVIEW` | Финальное интервью | Final interview | 4. Интервью | Активный |
| `OFFER` | Оффер | Offer | 5. Оффер | Финальный ✓ |
| `ACCEPTED` | Оффер принят | Offer accepted | 5. Оффер | Финальный ✓ |
| `REJECTED` | Отказ | Rejected | — | Финальный ✕ |
| `DECLINED` | Я отказался | Declined by me | — | Финальный |
| `NO_RESPONSE` | Нет ответа | No response | — | Финальный (вручную или авто) |

**FR-STATUS-2. Карточка отклика** — открывается боковой панелью по клику на строку:
- Все поля отклика, редактируемые inline (автосохранение с индикатором «Сохранено»).
- **Таймлайн статусов**: вертикальная шкала с датами каждого перехода и комментариями.
- При смене статуса — опциональный комментарий и дата события (по умолчанию — сегодня).
- Для отказа — опциональная причина (справочник: «Опыт», «Зарплата», «Закрыта вакансия», «Без объяснения», свой вариант).
- Для интервью — дата/время следующего этапа, формат (онлайн/офлайн), имя интервьюера.
- Для оффера — сумма предложения (для сравнения с вилкой вакансии).
- Действия: дублировать, архивировать, удалить (мягкое удаление, восстановление 30 дней).

**FR-STATUS-3. История** — каждый переход записывается в `status_history`; это основа расчёта конверсий по «максимально достигнутому этапу» и времени ответа.

**FR-STATUS-4. Авто-гостинг** — ежедневная задача (cron в NestJS `@nestjs/schedule`) помечает отклики в статусах `APPLIED`/`VIEWED` без изменений дольше порога (настройка пользователя) флагом «Нет ответа» (не меняя статус без согласия: на дашборде показывается подсказка «12 откликов без ответа > 14 дней. Перевести в „Нет ответа“?»).

### 5.5. Дашборды и аналитика

**FR-DASH-1. Глобальный фильтр периода** для всех виджетов: 7 дней, 30 дней, 90 дней, год, всё время, произвольный. Сравнение с предыдущим периодом (дельта ▲/▼ в процентах).

**FR-DASH-2. Обзор (главный дашборд)**

| Виджет | Содержание |
|---|---|
| KPI-строка | Всего откликов · Response rate · Конверсия в интервью · Конверсия в оффер · Медианное время до первого ответа · Активные отклики |
| Воронка | Отклик → Ответ → Проверка → Интервью → Оффер, абсолютные числа и % от предыдущего и от первого этапа |
| Динамика | Линейный/столбчатый график откликов по неделям с наложением числа ответов |
| Тепловая карта активности | Календарь в стиле «contribution graph»: число откликов в день |
| Распределение статусов | Кольцевая диаграмма текущих статусов |
| Требуют внимания | Ближайшие интервью, отклики без ответа > N дней |

**FR-DASH-3. Аналитика по источникам** — таблица + горизонтальные столбцы: число откликов, response rate, конверсия в интервью и оффер по каждой площадке. Подсветка лучшего источника.

**FR-DASH-4. Аналитика по должностям** — то же по названиям должностей. Возможность группировать близкие должности вручную (например, «Frontend Developer» и «Frontend-разработчик» → группа «Frontend»).

**FR-DASH-5. Аналитика по локациям** — разрез по городам/странам и формату работы (офис / гибрид / удалёнка): число откликов, response rate, конверсии; диаграмма долей форматов.

**FR-DASH-6. Аналитика по зарплатам**
- Гистограмма распределения откликов по зарплатным корзинам (шаг настраивается, по умолчанию 50 000 ₽ / 1 000 $).
- Конверсия в интервью и оффер по корзинам — **ключевой инсайт: на какой вилке меня зовут чаще**.
- Медиана и квартили зарплат вакансий, на которые откликался.
- Сравнение предложенной в оффере суммы с заявленной вилкой.
- Зарплаты в разных валютах не смешиваются: разрез по выбранной валюте (конвертация по курсу — этап 2).

**FR-DASH-7. Прочие разрезы** — влияние сопроводительного письма на response rate; день недели отправки vs ответы; причины отказов.

**FR-DASH-8. Формулы метрик**

Пусть `N` — число откликов за период (по дате отклика), `maxStage(a)` — максимальный этап, достигнутый откликом по истории статусов.

| Метрика | Формула |
|---|---|
| Response rate | `count(a: maxStage ≥ 2 или status = REJECTED после ответа компании) / N` — любой ответ компании, включая отказ |
| Конверсия в интервью | `count(maxStage ≥ 4) / N` |
| Конверсия в оффер | `count(maxStage ≥ 5) / N` |
| Конверсия интервью → оффер | `count(maxStage ≥ 5) / count(maxStage ≥ 4)` |
| Доля отказов | `count(status = REJECTED) / N` |
| Гостинг | `count(без ответа > порога) / N` |
| Время до первого ответа | медиана `(дата первого перехода из APPLIED/VIEWED) − (дата отклика)` |
| Длительность процесса | медиана `(дата финального статуса) − (дата отклика)` |

- Все проценты округляются до 1 знака.
- При `N < 10` в разрезе виджет показывает метку **«Мало данных»** и приглушённое значение, чтобы пользователь не делал выводов по шуму.
- Агрегаты считаются на бэкенде SQL-запросами (`GROUP BY`, оконные функции), а не на клиенте.

**FR-DASH-9. Инсайты** — блок из 2–4 автоматически сгенерированных текстовых наблюдений на основе правил, например:
- «С LinkedIn вы получаете ответы в 2,3 раза чаще, чем с HeadHunter».
- «На вакансии с вилкой 250–300 тыс. ₽ конверсия в интервью — 18 %, выше — 4 %».
- «Отклики с сопроводительным письмом получают ответ на 11 п. п. чаще».

Показываются только при достаточной выборке (≥ 10 откликов в каждой сравниваемой группе).

### 5.6. Импорт и экспорт
- Экспорт откликов в CSV / XLSX / JSON с учётом текущих фильтров.
- Импорт из CSV с мастером сопоставления колонок и предпросмотром (этап 2).

### 5.7. Уведомления (этап 2)
- Напоминание о предстоящем интервью (in-app + e-mail).
- Еженедельный дайджест со статистикой.

## 8. Визуальная концепция и UI/UX

### 8.1. Настроение
**«Дневник охоты»** — спокойный, собранный инструмент. Не корпоративная CRM и не «ИИ-стартап»: мягкие сливово-розовые тона, много воздуха, крупная типографика цифр, ощущение аккуратного личного журнала. Главный герой интерфейса — **цифры и воронка**, а не декор.

### 8.2. Ограничения палитры
**Запрещены:** синий (в т.ч. голубой, циан, индиго с синим уклоном), зелёный (включая бирюзовый), оранжевый, жёлтый, коричневый (включая бежево-коричневые «кофейные» тона).
**Разрешённое семейство:** слива, фиолетовый, орхидея, фуксия, малиновый, роза, винный, лавандовый, графит, нейтральные серые с лиловым подтоном.

### 8.5. Типографика
- **Основной шрифт:** Onest (Google Fonts, отличная кириллица) — UI, текст. Альтернатива — Manrope.
- **Акцидентный:** Unbounded — только заголовки страниц и крупные KPI-цифры.
- Цифры в таблицах и KPI — `font-variant-numeric: tabular-nums`.
- Шкала: 12 / 14 / 16 / 20 / 28 / 40 / 64 px. KPI-значения — 40–64 px, вес 500, трекинг −2 %.
- Заголовки — обычный регистр, без капса; капс только для микро-лейблов 11 px с трекингом +6 %.

### 8.6. Форма и пространство
- Радиусы: 10 px — поля и кнопки, 16 px — карточки, 24 px — крупные панели, бейджи — pill.
- Сетка 8 px; отступы между блоками дашборда — 24 px, по краям страницы — 32 px (desktop), 16 px (mobile).
- Тени минимальные: `0 1px 2px rgb(31 23 36 / 6%), 0 8px 24px -12px rgb(122 46 142 / 12%)`; в тёмной теме — вместо теней обводка `--border`.
- Плотность таблицы: «Комфортная» (52 px строка) / «Компактная» (40 px) — переключатель.

### 8.7. Движение
- Появление виджетов дашборда — каскадный fade-up (40 мс шаг, 240 мс длительность).
- Числа KPI — анимированный счётчик при загрузке и смене периода.
- Боковые панели — slide-in 220 мс, `cubic-bezier(.2,.8,.2,1)`.
- Смена темы — плавный переход цветов 200 мс (без мерцания при загрузке: тема применяется до гидратации).
- Всё отключается при `prefers-reduced-motion: reduce`.

### 8.8. Экраны

**Э-1. Лендинг / вход.** Двухцветный диптих: левая часть — мягкий сливово-розовый градиент с крупной фразой «Каждый отклик — в цифрах» и живым фрагментом воронки (декоративный, реальные цифры демо); правая — минималистичная форма входа на `--surface`. Переключатели языка и темы в правом верхнем углу.

**Э-2. Каркас приложения.** Слева — узкий сайдбар (иконки + подписи, сворачиваемый до 72 px): Обзор, Отклики, Аналитика (Источники, Должности, Локации, Зарплаты), Справочники, Настройки. Сверху — поиск (⌘K), переключатели RU/EN и темы, аватар, главная кнопка «+ Отклик» (primary, всегда видна). На мобильных — нижняя навигация из 4 пунктов и плавающая кнопка «+».

**Э-3. Обзор (дашборд).** Модульная бенто-сетка 12 колонок:
- Верхний ряд: крупная hero-карточка на градиенте (2/3 ширины) — главное число «Конверсия в интервью 14,2 %» и мини-воронка; справа столбец из трёх компактных KPI.
- Второй ряд: полноширинная воронка с подписями конверсий между этапами.
- Третий ряд: динамика по неделям (2/3) + кольцо статусов (1/3).
- Четвёртый ряд: тепловая карта активности (полная ширина) и блок «Требуют внимания».
- Блок «Инсайты» — карточки с крупной цифрой и одной строкой текста.

**Э-4. Отклики.** Над таблицей — строка поиска, чипы фильтров, переключатель Таблица/Канбан/Лента, кнопка настройки колонок. Таблица без вертикальных линий, только горизонтальные разделители; ховер строки — `--surface-2`; компания выводится с монограммой-аватаром (первая буква на тонированном фоне из палитры). Поля сгруппированы: «Главное» (компания, должность, ссылка) — крупные поля 48 px; «Детали» (источник, локация, формат, зарплата, дата, статус) — компактная сетка 2 колонки; «Заметки» свёрнуты по умолчанию. Внизу — sticky-футер: «Сохранить» (primary), «Сохранить и ещё» (outline), подсказки горячих клавиш мелким текстом.

**Э-6. Карточка отклика.** Боковая панель 560 px: шапка с компанией, должностью и крупным бейджем статуса-селектором; под ней — горизонтальный степпер этапов воронки (пройденные — заливка `--primary`); ниже вкладки «Детали» / «История». История — вертикальный таймлайн с точками цвета статуса.

**Э-7. **Э-8. Справочники.** Вкладки по типам; список значений с числом использований, кнопки «Переименовать», «Объединить», «Удалить»; выделение нескольких записей → «Объединить в…».

- Брейкпоинты: 360, 768, 1024, 1280, 1536 px.
- Мобильная версия — полноценная (главный сценарий «откликнулся с телефона → внёс»): лента вместо таблицы, bottom sheet формы, графики с горизонтальной прокруткой не допускаются — они перестраиваются в вертикальные списки.

## 9. Локализация

- Языки: **ru** (по умолчанию), **en**. Первичный выбор — по `Accept-Language`, затем из профиля.
- Переключатель языка — в шапке и в настройках; смена языка без перезагрузки и без потери состояния фильтров.
- Все строки интерфейса — в файлах сообщений `messages/ru.json`, `messages/en.json` с ICU-плюрализацией («1 отклик / 2 отклика / 5 откликов», «1 application / 5 applications»).
- Даты, числа, валюты — через `Intl` с учётом локали (`15 000 ₽` / `₽15,000`).
- Статусы, источники-предустановки, причины отказов, тексты инсайтов, ошибки API (по коду) — локализуются. Пользовательские значения справочников — не переводятся.
- Тесты: проверка отсутствия непереведённых ключей в CI.

## 10. Нефункциональные требования

### 10.1. Производительность
- LCP ≤ 1,5 с, INP ≤ 200 мс, CLS ≤ 0,05 на дашборде.
- Ответ подсказок справочника ≤ 100 мс (p95), с debounce 120 мс на клиенте.
- Аналитические запросы ≤ 300 мс (p95) при 5 000 откликов.
- Таблица плавно прокручивается при 5 000 строк (виртуализация).

### 10.2. Безопасность
- Пароли — argon2id. Токены — только в httpOnly cookie.
- Helmet, строгий CORS (только домен фронтенда), CSP.
- Валидация всех входных данных на бэкенде; ORM-параметризованные запросы.
- Проверка владельца на каждом обращении к ресурсу (guard + фильтр `userId` в репозитории).

## 13. Критерии приёмки

1. Пользователь регистрируется, входит, остаётся авторизованным 30 дней без повторного ввода пароля; после истечения access-токена сессия продлевается прозрачно.
2. Отклик с компанией и должностью добавляется с клавиатуры (N → ввод → Enter) за ≤ 15 секунд.
3. Новое название компании/должности/локации/источника после сохранения появляется в подсказках при следующем добавлении; повторный ввод того же названия в другом регистре не создаёт дубль.
4. Смена статуса из таблицы занимает не более 2 кликов и сразу отражается в метриках дашборда.
5. Значения конверсий на дашборде совпадают с ручным расчётом по формулам п. 5.5 на тестовом наборе из 50 откликов.
6. Все экраны корректно отображаются в светлой и тёмной теме, переключение мгновенное и сохраняется.
7. Весь интерфейс переведён на RU и EN, включая статусы, ошибки, даты и числа; непереведённых ключей нет.
8. В интерфейсе отсутствуют синий, зелёный, оранжевый, жёлтый и коричневый цвета (проверка по токенам и визуальным тестам).
9. Пользователь A не может получить данные пользователя B ни через UI, ни прямыми запросами к API.
10. Lighthouse: Performance ≥ 90, Accessibility ≥ 95 на дашборде и списке откликов.
