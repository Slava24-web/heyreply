## Что проверено и в порядке

- **Секреты в репозитории.** `.env`-файлы в `.gitignore`, токенов и ключей в коде нет. В образы `.env` не попадает (`.dockerignore`), секреты передаются только через переменные окружения. Локальный `.env` с правами 600.
- **Хранение паролей.** argon2id (m=64 МБ, t=3, p=4) с автоматическим перехэшированием при смене параметров. Политика пароля: 8–128 символов, буква и цифра.
- **Токены.** Access JWT (HS256, алгоритм зафиксирован при проверке, `alg: none` и подделка подписи отклоняются), 15 минут, привязан к сессии через `sid`. Refresh хранится в БД только в виде SHA-256. Все cookie `httpOnly`, `SameSite=Lax`, refresh ограничен путём `/api/v1/auth`. Из JavaScript виден только `NEXT_LOCALE`.
- **Ротация refresh-токена.** Каждый refresh выдаёт новый токен. Повторное использование старого вне окна гонки отзывает все сессии (тест).
- **CSRF.** `SameSite=Lax` и проверка `Origin` + `Sec-Fetch-Site` на всех изменяющих запросах: кросс-доменные POST дают 403 (тест). CORS разрешён только для `WEB_ORIGIN`. GET-эндпоинты не меняют состояние.
- **XSS.** React экранирует вывод, `dangerouslySetInnerHTML` и `eval` не используются. CSP: `script-src 'self' 'nonce-…' 'strict-dynamic'`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`. Все 21 скрипт на странице с nonce, нарушений CSP в консоли нет.
- **IDOR и изоляция данных.** Каждый запрос фильтруется по `userId` из токена. Чужие отклики, справочники и сессии недоступны: 404, проверено тестом для чтения, изменения и удаления. ID валидируются как UUID.
- **Инъекции.** Только Prisma с параметризацией, raw SQL — лишь `SELECT 1` в health-check. Все входные данные проходят Zod; лишние поля отбрасываются (нет mass assignment).
- **Ошибки.** Единый фильтр не отдаёт стек-трейсы и внутренние детали (тест). Лимит тела запроса 100 КБ в API и 1 МБ на edge.
- **Логи.** Персональных данных, паролей и токенов в логах нет (проверено на запущенном стеке).
- **Сброс пароля.** Одноразовый токен, 256 бит, в БД хэш, срок 1 час. После сброса все сессии завершаются. Ответ не раскрывает, существует ли e-mail.
- **Открытый редирект.** Параметр `next` принимает только относительный путь и всегда получает префикс локали.
- **Удаление аккаунта.** Каскадно удаляются пользователь, сессии, отклики, история, справочники и теги (тест).

## Персональные данные

| Данные | Где | Защита |
|---|---|---|
| E-mail, имя | `User` | Доступ только владельцу; удаление по запросу |
| Пароль | `User.passwordHash` | argon2id, исходник не хранится и не логируется |
| IP, user-agent | `Session` | Нужны для списка устройств; удаляются вместе с сессией, мёртвые сессии чистятся |
| Заметки, компании, зарплаты | `Application` и справочники | Изоляция по `userId`, экспорт и удаление по запросу (152-ФЗ / GDPR) |
| Черновик формы, настройки вида | localStorage браузера | Очищаются при выходе и истечении сессии |

## Остаточные риски и рекомендации

1. **Шифрование диска БД.** Данные в Postgres хранятся в открытом виде на диске сервера. Бэкапы шифруются age перед загрузкой (сделано, `docs/DEPLOY.md`). Осталось включить шифрование тома или диска сервера у хостера.
2. **Edge-прокси обязателен.** Без Caddy (или nginx с `proxy_set_header X-Forwarded-For $remote_addr`) перед Next IP-лимиты обходятся подменой заголовка. Лимит попыток на аккаунт (30 за 15 минут) от IP не зависит и продолжает действовать.
3. **Несколько инстансов API.** Счётчики попыток входа и rate limit хранятся в памяти. При масштабировании перенесите их в Redis (`@nestjs/throttler` storage + `LoginAttempts`).
4. **Перечисление e-mail при регистрации.** Ответ `EMAIL_TAKEN` раскрывает существование аккаунта. Это осознанный компромисс ради понятного UX. Если нужно скрыть, отправляйте письмо «аккаунт уже существует» вместо ошибки (требуется почтовый транспорт).
5. **Почта.** Сброс пароля отправляет письмо через SMTP (`SMTP_URL`, `MAIL_FROM`, `docs/DEPLOY.md`, раздел 5). Без настройки SMTP сброс в production не работает. Письмо не чаще раза в минуту на аккаунт, ответ не зависит от существования адреса (отправка не ждётся).
6. **`style-src 'unsafe-inline'`.** Нужен графикам и анимациям (inline-атрибуты `style`). Это не позволяет выполнять скрипты, но допускает CSS-инъекции, если когда-нибудь появится вывод HTML без экранирования.
7. **`braces` (high) в dev-зависимостях ESLint.** Исправленной версии пока нет. В рантайм и образы не попадает.
8. **2FA** не реализована. Для сервиса с персональными данными стоит добавить TOTP как опцию.
